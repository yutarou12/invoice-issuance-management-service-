# コーディング規約

## TypeScript・JavaScript

[TypeScript Deep Dive 日本語版](https://typescript-jp.gitbook.io/deep-dive/styleguide)を基準とする。

- インデントはスペース2文字、文字列はシングルクォート、セミコロンあり。Prettierで整形する。
- 変数・関数はcamelCase、型・コンポーネントはPascalCase。interfaceにI接頭辞を付けない。
- ファイル名は用途が分かる名前。ReactコンポーネントはPascalCase、その他は小文字。
- 型はstrictモード。anyを使用せず、外部入力はunknownとして検証する。
- データ形状にはinterface、状態や選択肢にはunion型を使用する。
- constを優先し、再代入が必要な場合だけletを使用する。varは使用しない。
- 厳密比較を使用する。欠損値は原則undefined、ライブラリAPIのnullは許容する。
- 公開APIはZodで検証し、金額は日本円の整数として扱う。
- SQLはパラメータバインドし、複数行の更新にはトランザクションを使用する。
- コメントは日本語で、意図・制約・副作用を説明する。処理をそのまま言い換えるコメントは避ける。
- 非同期処理の失敗を握りつぶさず、画面には利用者向けの文言、サーバーには必要最小限の情報を出す。
- 秘密情報・パスワード・メール本文をログに出さない。

## React・CSS

- 関数コンポーネントとHooksを使用し、共有するAPI型はsharedへ置く。
- 一覧取得のEffectにはクリーンアップを設け、古いレスポンスの上書きを防ぐ。
- フォームにはラベル・必須指定・適切な入力型を設ける。サーバーでも再検証する。
- MUIの標準キーボード操作を利用し、意味のあるbutton・nav・main・tableを使用する。
- [デジタル庁デザインシステム](https://design.digital.go.jp/)の配色・余白・ラベルを参考にする。公式準拠認証を意味しない。
- 状態は色だけに依存せず文字ラベルを併記。フォーカスを視認できるようにする。
- 外部CDNを使用せず、フォントを含めローカル配信する。

## SQL・Docker・運用

- SQLキーワードは大文字、テーブル名は小文字。破壊的な操作を自動実行しない。
- コンテナは非rootで実行し、DBだけを永続ボリュームへ保存する。
- パッケージはpackage-lock.jsonを管理し、再現可能なnpm ciを使用する。
- .envは管理対象外。共有する設定例には秘密を含めない。
- ファイル削除には利用者の事前承認が必要。削除APIや自動クリーンアップ処理を作らない。

## 最小限の検証

npm run buildで型・本番ビルドを検証する。npm testでCSVの原子性、状態遷移、送信失敗、入力検証、認証を確認する。低影響な表示だけを写すテストは追加しない。
